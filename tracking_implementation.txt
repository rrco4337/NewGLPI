TRACKING IMPLEMENTATION — Import CSV Mouvements + Détail par ItemType
======================================================================

ÉTAPE A — L'affichage à blanc / sans rien
------------------------------------------
Le développeur crée d'abord la page CsvMvtImport vide pour voir si elle apparaît
dans l'application. Il ajoute juste un <h2> et vérifie que la route fonctionne.
Ensuite il ajoute aussi l'entrée dans la sidebar (DashboardLayout) pour pouvoir
y accéder facilement. Il teste en cliquant sur le lien dans le menu.

Pour ItemsCostList, il voit que le type d'item est déjà dans le tableau, mais
il veut pouvoir cliquer dessus. Il commence par ajouter un simple onClick sur
la cellule pour voir si ça réagit, avec un console.log("cliqué !").

ÉTAPE B — La modification de la table / structure de données
-------------------------------------------------------------
Aucune nouvelle table n'est nécessaire dans SQLite — les tables ticket_supercosts
et ticket_reopen_costs existent déjà dans server/api.ts et contiennent déjà les
champs ticket_id, batch, itemtype, items_id, amount.

Le développeur ajoute simplement un nouveau endpoint GET dans server/api.ts
pour récupérer les lignes filtrées par itemtype depuis les deux tables.

ÉTAPE C — La création des fonctions
------------------------------------
C1. server/api.ts — Nouveau endpoint GET /api/item-supercosts/details/:itemtype
    Requête SQLite sur ticket_supercosts WHERE itemtype = ? et pareil sur
    ticket_reopen_costs. Retourne { supercosts: [...], reopencosts: [...] }.

C2. src/api/itemSuperCost.ts — Nouvelle méthode getDetailsByItemtype(itemtype)
    Fait un fetch vers /api/item-supercosts/details/{itemtype}.
    Retourne { supercosts, reopencosts }.

C3. src/pages/BackOffice/CsvMvtImport.tsx — Création de la page
    - parseCSV(texte) : découpe les lignes par \n, les colonnes par virgule,
      skipke la première ligne si elle commence par "ticket".
    - onChoixFichier() : lit le fichier avec FileReader et appelle parseCSV.
    - onImporter() : boucle sur chaque ligne du CSV :
        * mvt === 'open'   → ItemSuperCostApi.addReopenCost(ticket, valeur)
        * mvt === 'cancel' → ItemSuperCostApi.cancelLastBatch(ticket)
        * mvt === 'close'  → glpiTicketService.getTicketLinkedItems(ticket)
                             puis ItemSuperCostApi.addSuperCost(ticket, valeur, items)

C4. src/pages/BackOffice/ItemsCostList.tsx — Ajout de la fonction ouvrirDetail()
    - Toggle : si le même itemtype est cliqué, ferme le détail.
    - Sinon : charge les données via ItemSuperCostApi.getDetailsByItemtype(itemtype).
    - Gère un état chargementDetail pour afficher "Chargement..." pendant la requête.

ÉTAPE D — L'utilisation des fonctions à la fin (connexion UI ↔ logique)
------------------------------------------------------------------------
D1. ItemsCostList.tsx — La cellule itemtype devient cliquable :
    onClick={() => ouvrirDetail(row.itemtype)} avec cursor:pointer et une flèche
    ▲/▼ selon l'état ouvert/fermé.
    Un bloc <div> sous le tableau principal affiche les deux sous-tableaux
    (supercosts et reopencosts) quand un itemtype est sélectionné.

D2. CsvMvtImport.tsx — Le bouton "Importer" appelle onImporter() et affiche
    un tableau des résultats (ticket, mvt, valeur, statut, message) une fois
    l'import terminé.

D3. appRoutes.tsx — Route /admin/csv-mvt ajoutée dans le DashboardLayout.
D4. DashboardLayout.tsx — Lien "Import CSV Mvt" ajouté dans la sidebar.
