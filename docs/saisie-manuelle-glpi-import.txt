PREREQUIS — ROUTE MANQUANTE
-----------------------------
/admin/import est dans la nav (DashboardLayout.tsx ligne 8) mais absent de appRoutes.tsx.
Il faut d'abord l'enregistrer, sinon la page n'est jamais rendue :

  // src/routes/appRoutes.tsx
  import { GlpiImport } from '@/pages/BackOffice/GlpiImport'  ← ajouter
  <Route path="import" element={<GlpiImport />} />             ← ajouter dans /admin


PARALLÈLE AVEC CsvMvtImport
-----------------------------
Dans CsvMvtImport :
  - traiterLigne(ticket, mvt, valeur) = source de vérité métier, ignorant l'origine des données
  - L'import CSV et la saisie manuelle appellent toutes les deux traiterLigne()
  - États séparés : miasa (CSV) vs manMiasa (manuel)

Dans GlpiImport, l'équivalent est :
  - runImport(assets, tickets, costs, images, onProgress, token) = source de vérité
  - L'import CSV appelle déjà runImport() avec des tableaux parsés depuis les fichiers
  - La saisie manuelle appellerait runImport() avec un tableau de 1 seul AssetRow
  - États séparés du state machine CSV (phase : upload/validating/validated/importing/done)


CE QU'ON PEUT SAISIR MANUELLEMENT
-----------------------------------
Un seul type d'objet par soumission : un asset (Computer, Monitor, Printer, etc.)

Le type AssetRow (src/lib/import/types.ts) définit les champs nécessaires :
  - itemType      : GlpiItemType  → <select> avec les types courants
  - name          : string        → <input> texte, OBLIGATOIRE
  - inventoryNumber: string       → <input> texte
  - status        : string        → <input> texte (résolu en ID par l'orchestrateur)
  - location      : string        → <input> texte (résolu en ID)
  - manufacturer  : string        → <input> texte (résolu en ID)
  - model         : string        → <input> texte (résolu en ID)
  - user          : string        → <input> texte (résolu en ID)
  - rowIndex      : number        → toujours 0 en saisie manuelle

Les champs status/location/manufacturer/model/user sont optionnels —
l'orchestrateur gère les valeurs vides (il met simplement 0 dans les dropdowns GLPI).

Types courants à proposer dans le <select> :
  Computer, Monitor, Printer, NetworkEquipment, Peripheral, Phone, Rack

FONCTION DE SOUMISSION
------------------------
async function handleManualSubmit() {
  if (!manName.trim()) return
  setManSaving(true)
  const token = localStorage.getItem('glpi_session_token') ?? undefined
  try {
    const result = await runImport(
      [{
        rowIndex: 0,
        itemType: manItemType,
        name: manName.trim(),
        inventoryNumber: manInvNum.trim(),
        status: manStatus.trim(),
        location: manLocation.trim(),
        manufacturer: manManufacturer.trim(),
        model: manModel.trim(),
        user: manUser.trim(),
      }],
      [],     // pas de tickets
      [],     // pas de coûts
      [],     // pas d'images
      () => {},  // pas de barre de progression (1 seul item)
      token,
    )
    const ok = result.success && result.errors.length === 0
    const nbCreated = result.created.computers + result.created.monitors + result.created.otherAssets
    setManResults(prev => [{
      name: manName.trim(),
      ok,
      message: ok
        ? `${manItemType} créé (${nbCreated} item GLPI)`
        : (result.errors[0] ?? 'erreur inconnue'),
    }, ...prev])
    if (ok) {
      setManName('')
      setManInvNum('')
    }
  } catch (e: unknown) {
    setManResults(prev => [{
      name: manName.trim(),
      ok: false,
      message: e instanceof Error ? e.message : 'erreur inconnue',
    }, ...prev])
  }
  setManSaving(false)
}

POINTS D'ATTENTION
--------------------

0. APPEL API PARASITE — ensureImageDocumentTypes(token) est appelé à la ligne 291
   de importOrchestrator.ts MÊME QUAND images = []. C'est un appel à l'endpoint GLPI
   DocumentType qui se produit avant la boucle d'images vide. Conséquence : si GLPI
   refuse cet endpoint (droits insuffisants ou endpoint absent), la saisie manuelle
   d'un asset échouera ici même sans image. Pas bloquant si l'import CSV fonctionne
   déjà, mais point de fragilité à connaître.

0b. PERFORMANCE — resolver.preloadAll(token) recharge tous les dropdowns GLPI à
   chaque soumission manuelle. Pour le CSV c'est fait une seule fois pour N lignes.
   Ici ce sera refait à chaque asset créé. Pas un bug, mais peut être lent si
   l'utilisateur crée plusieurs assets à la suite.

1. L'orchestrateur gère le rollback automatiquement si la création échoue à mi-chemin.
   Une saisie manuelle bénéficie donc du même mécanisme de sécurité que l'import CSV.

2. Le token GLPI est lu depuis localStorage (même logique que handleImport dans GlpiImport).
   Si l'utilisateur n'est pas authentifié, runImport lèvera une erreur capturée dans le catch.

3. onProgress est passé comme () => {} car 1 seul item = pas besoin d'une barre de progression.
   Si on veut quand même afficher un spinner, utiliser manSaving (déjà dans l'état).

4. La section manuelle est indépendante du state machine CSV (phase).
   Elle reste visible et utilisable même si un CSV est en train d'être validé ou importé.
   Seule exception possible : désactiver le bouton si phase === 'importing' pour éviter
   deux appels concurrents à runImport sur la même session GLPI.

5. Les champs status/location/manufacturer/model/user sont des strings libres.
   L'orchestrateur (DropdownResolver) crée automatiquement la valeur dans GLPI si elle
   n'existe pas encore (comportement identique à l'import CSV).

6. Pour les tickets et coûts manuels, même principe :
   - Ticket : passer [] en assets, un TicketRow en tickets, [] en costs
   - Coût : nécessite que le ticket existe déjà dans GLPI (refTicket doit être valide)
   Ces cas sont moins prioritaires que l'asset car CsvMvtImport couvre déjà les coûts.
