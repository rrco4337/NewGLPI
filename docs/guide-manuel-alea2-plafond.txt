==============================================================================
GUIDE MANUEL — ALÉA 2 : PLAFOND DE RÉOUVERTURE (par ticket)
==============================================================================

But : limiter le cumul des frais de réouverture d'un TICKET à un pourcentage
de la somme de SES Super Cost. Le plafond se définit ticket par ticket
(un seul plafond par ticket).

  plafondMax(ticket) = (somme des Super Cost actifs du ticket) x (% du ticket / 100)

Règle clé d'archi : GET /reopens RECALCULE le montant à partir du `percent`
stocké (il ignore le montant en base). Donc on matérialise le plafond en
RÉDUISANT le `percent` effectif stocké, pas le montant.

3 fichiers à modifier :
  1) server/api.ts                       (backend + stockage)
  2) src/api/itemSuperCost.ts            (client API)
  3) src/pages/BackOffice/ReopenList.tsx (UI)

Les numéros de ligne ci-dessous correspondent à l'état ACTUEL du dépôt (après
implémentation). Si tu repars d'une base sans Aléa 2, repère plutôt les ANCRES
de texte indiquées : elles sont stables.

    (db.prepare('SELECT COALESCE(SUM(amount), 0) as s FROM ticket_supercosts WHERE cancelled = 0 AND ticket_id = ?').get(ticketId) as { s: number }).s

  // Total dynamique des frais de réouverture non fermés du ticket
  // (même calcul que GET /reopens).
  const sumReopenCosts = (ticketId: number): number => {
    const scIndex = buildScIndex()
    const rows = db.prepare('SELECT ticket_id, itemtype, items_id, batch, mode, percent FROM ticket_reopen_costs WHERE closed = 0 AND ticket_id = ?').all(ticketId) as
      { ticket_id: number; itemtype: string; items_id: number; batch: number; mode: number; percent: number }[]
    let total = 0
    for (const r of rows) {
      const sorted = [...(scIndex.get(`${r.ticket_id}|${r.itemtype}|${r.items_id}`) ?? [])].sort((a, b) => a.batch - b.batch)
      total += computeBaseAmount(sorted, r.mode, r.batch) * (r.percent / 100)
    }
    return total
  }

  // Définir / mettre à jour / supprimer le plafond d'un ticket (un seul par ticket).
  app.put('/api/item-supercosts/ceilings/:ticketId', (req, res) => {
    const ticketId = Number(req.params.ticketId)
    const { percent } = req.body as { percent: number | null }
    if (percent === null || percent === undefined || isNaN(Number(percent))) {
      db.prepare('DELETE FROM ticket_reopen_ceilings WHERE ticket_id = ?').run(ticketId)
      res.json({ ticketId, percent: null }); return
    }
    db.prepare('INSERT INTO ticket_reopen_ceilings (ticket_id, percent) VALUES (?, ?) ON CONFLICT(ticket_id) DO UPDATE SET percent = excluded.percent').run(ticketId, Number(percent))
    res.json({ ticketId, percent: Number(percent) })
  })

3. Scénario métier :

   - Tenter une réouverture de 40 % (mode 1) -> elle est limitée à 30 (dispo = 30).

   - Laisser le champ % vide et enregistrer -> le plafond du ticket est supprimé.

==============================================================================
NOTES
==============================================================================
- Le pourcentage est défini PAR TICKET (table ticket_reopen_ceilings, PK ticket_id).
- "Mode négligeable" : inexistant dans le modèle actuel (modes 1-4), donc aucune
  ligne à exclure de la base du plafond.
- Les Super Cost annulés (cancelled = 1) sont déjà exclus de la base.
- Le plafond n'est imposé qu'à la CRÉATION d'une réouverture. Le "disponible"
  affiché se recalcule à chaque rechargement à partir des Super Cost courants.
