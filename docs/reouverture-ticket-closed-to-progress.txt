OBJECTIF
--------
Lorsqu'un ticket à l'état "Closed" est drag-and-droppé vers la colonne "In Progress"
dans le Kanban Front Office, afficher un dialog proposant 2 choix :

  1. Bouton "Annulation (effacer le coût)" :
     → Remet le ticket en In Progress (status 2)
     → Efface (remet à 0) le Super Cost précédemment enregistré pour ce ticket

  2. Champ "% Réouverture" + bouton "Réouvrir avec ce %" :
     → L'utilisateur saisit un pourcentage (ex: 50)
     → Le nouveau Super Cost = SuperCost précédent × (pourcentage / 100)
     → Remet le ticket en In Progress (status 2)
     → Sauvegarde le nouveau Super Cost calculé

Le bouton "Fermer" (gris) ferme le dialog sans effectuer aucun changement.

CODE AJOUTÉ :

  const cancelReopenDialog = () => {
    setReopenDialog(null)
    setReopenPct('')
  }

  const handleReopenAnnulation = async () => {
    if (!reopenDialog) return
    setReopenSaving(true)
    const { ticketId, prevStatus } = reopenDialog
    setTickets(prev => prev.map(t => t.id === ticketId ? { ...t, status: 2 } : t))
    try {
      await glpiTicketService.updateTicket(ticketId, { status: 2 })
      await KanbanSettingApi.clearSuperCost(ticketId)
      setReopenDialog(null)
      setReopenPct('')
    } catch (err) {
      console.error('Failed to reopen ticket:', err)
      setTickets(prev => prev.map(t => t.id === ticketId ? { ...t, status: prevStatus } : t))
      setError('Erreur lors de la réouverture du ticket.')
    } finally {
      setReopenSaving(false)
    }
  }

  const handleReopenWithPct = async () => {
    if (!reopenDialog) return
    const pct = parseFloat(reopenPct)
    if (isNaN(pct) || pct < 0) return
    setReopenSaving(true)
    const { ticketId, prevStatus, previousSuperCost } = reopenDialog
    const newCost = previousSuperCost * (pct / 100)
    setTickets(prev => prev.map(t => t.id === ticketId ? { ...t, status: 2 } : t))
    try {
      await glpiTicketService.updateTicket(ticketId, { status: 2 })
      await KanbanSettingApi.saveSuperCost(ticketId, newCost)
      setReopenDialog(null)
      setReopenPct('')
    } catch (err) {
      console.error('Failed to reopen ticket with cost:', err)
      setTickets(prev => prev.map(t => t.id === ticketId ? { ...t, status: prevStatus } : t))
      setError('Erreur lors de la réouverture du ticket.')
    } finally {
      setReopenSaving(false)
    }
  }

EXPLICATION :
  - cancelReopenDialog() : ferme le dialog sans rien faire (Fermer).
  - handleReopenAnnulation() :
      * Mise à jour optimiste → status 2
      * updateTicket(status: 2) → GLPI
      * clearSuperCost() → remet le Super Cost à 0 dans SQLite
      * Rollback si erreur API
  - handleReopenWithPct() :
      * Calcule newCost = previousSuperCost × (pct / 100)
      * Mise à jour optimiste → status 2
      * updateTicket(status: 2) → GLPI
      * saveSuperCost(newCost) → SQLite
      * Rollback si erreur API

POINTS D'ATTENTION
================================================================================

1. L'API backend /settings/{key} doit supporter un PUT sur une clé inexistante
   (upsert). C'est le cas selon le comportement constaté pour saveSuperCost.

2. Le calcul est : nouveau_coût = super_cost_précédent × (pourcentage / 100)
   → 100% = même coût, 50% = demi-coût, 0% = 0€

3. Le dialog de réouverture n'apparaît QUE pour Closed → In Progress.
   Closed → New reste un changement direct sans dialog.

4. En cas d'erreur API lors de la réouverture, un rollback optimiste est effectué
   (le ticket reprend son status "closed" dans l'UI).

5. Le champ % accepte des valeurs décimales (step="1" mais parseFloat accepte 50.5).
