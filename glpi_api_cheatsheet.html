Session & Auth

Initialiser une session

GET/apirest.php/initSession

Headers obligatoires :

Authorization: user_token VOTRE_TOKEN
App-Token: VOTRE_APP_TOKEN
Content-Type: application/json

Réponse :

{ "session_token": "abc123xyz..." }

Stocker le session_token — à envoyer dans TOUS les appels suivants.

Header à inclure dans chaque requête

Session-Token: abc123xyz...
App-Token: VOTRE_APP_TOKEN
Content-Type: application/json

Fermer la session

GET/apirest.php/killSession

À appeler proprement à la fin pour libérer la session côté GLPI.

Exemple axios (TypeScript)

const api = axios.create({
  baseURL: 'http://localhost/glpi/apirest.php',
  headers: {
    'App-Token': APP_TOKEN,
    'Content-Type': 'application/json'
  }
})

const { data } = await api.get('/initSession', {
  headers: { Authorization: `user_token ${USER_TOKEN}` }
})
api.defaults.headers['Session-Token'] = data.session_token

Items liés à un ticket

Comment GLPI stocke les liens item ↔ ticket

GLPI utilise une table pivot glpi_items_tickets avec les colonnes tickets_id, items_id, itemtype.

L'objet API correspondant est Item_Ticket. Chaque ligne représente un lien entre un ticket et un item d'un type donné.

Récupérer tous les items d'un ticket

GET/Ticket/{id}/Item_Ticket
GET /Ticket/42/Item_Ticket?range=0-999

Réponse (exemple) :

[
  { "id": 1, "tickets_id": 42, "items_id": 7, "itemtype": "Computer" },
  { "id": 2, "tickets_id": 42, "items_id": 3, "itemtype": "Monitor" }
]
itemtype est un string items_id dépend du type

Coûts

Où GLPI stocke les coûts

Les coûts sont dans la table glpi_ticketcosts, jamais directement sur le ticket. L'objet API est TicketCost. Il peut y avoir plusieurs enregistrements par ticket.

Le "coût total" affiché dans l'interface GLPI est calculé dynamiquement : (cost_time × actiontime/3600) + cost_fixed + cost_material.

Récupérer les coûts d'un ticket

GET/Ticket/{id}/TicketCost
GET /Ticket/42/TicketCost?range=0-999

Réponse :

[
  {
    "id": 1,
    "tickets_id": 42,
    "name": "Coût intervention",
    "actiontime": 3600,
    "cost_time": "100.0000",
    "cost_fixed": "50.0000",
    "cost_material": "25.0000",
    "begin_date": "2026-06-01",
    "end_date": "2026-06-05"
  }
]
PIÈGE : cost_time, cost_fixed, cost_material sont des strings

Interface TypeScript

interface TicketCost {
  id: number
  tickets_id: number
  name?: string
  actiontime: number          // durée en secondes
  cost_time: string | number  // taux horaire — ATTENTION: string retourné
  cost_fixed: string | number
  cost_material: string | number
  begin_date?: string
  end_date?: string
  budgets_id?: number
}

Calcul du coût total (glpiCost)

const getGlpiCost = async (ticketId: number): Promise<number> => {
  const res = await api.get(`/Ticket/${ticketId}/TicketCost`, {
    params: { range: '0-999' }
  })
  const costs: TicketCost[] = res.data

  return costs.reduce((sum, c) =>
    sum
    + Number(c.cost_time || 0) * ((c.actiontime || 0) / 3600)
    + Number(c.cost_fixed || 0)
    + Number(c.cost_material || 0),
  0)
}
Number() convertit "100.0000" → 100

Fonction complète TypeScript

async function computeCostPerItem(ticketId: number, superCost: number) {
  // 1. Items
  const itemsRes = await api.get(`/Ticket/${ticketId}/Item_Ticket`,
    { params: { range: '0-999' } })
  const items: ItemTicket[] = itemsRes.data
  const nombreItems = items.length
  if (nombreItems === 0) return []

  // 2. Coût GLPI
  const costsRes = await api.get(`/Ticket/${ticketId}/TicketCost`,
    { params: { range: '0-999' } })
  const glpiCost = (costsRes.data as TicketCost[]).reduce((sum, c) =>
    sum + Number(c.cost_time||0) * ((c.actiontime||0)/3600)
        + Number(c.cost_fixed||0) + Number(c.cost_material||0), 0)

  // 3. Calcul
  const costParItem = (superCost + glpiCost) / nombreItems

  // 4. Détails items (catégorie)
  return Promise.all(items.map(async (item) => {
    const detail = await api.get(`/${item.itemtype}/${item.items_id}`,
      { params: { expand_dropdowns: true } })
    return {
      idTicket: ticketId,
      idItem: item.items_id,
      itemtype: item.itemtype,
      category: detail.data[`${item.itemtype.toLowerCase()}types_id`] ?? 'N/A',
      superCost,
      glpiCost,
      costParItem
    }
  }))
}

Pièges & erreurs fréquentes

Espace dans le nom de paramètre

'tickets_id ' avec un espace → GLPI ignore le filtre et retourne tout. Toujours vérifier les noms de paramètres.

cost_time, cost_fixed, cost_material sont des strings

GLPI retourne "100.0000" (string). Faire + donne une concaténation. Toujours utiliser Number() ou parseFloat().

Item_Ticket : ne pas filtrer via /Item_Ticket/ global

Utiliser /Ticket/{id}/Item_Ticket (sous-ressource). L'endpoint global /Item_Ticket ne supporte pas bien le filtre par tickets_id via query param.

items_id n'est pas unique — dépend de itemtype

items_id: 3 peut désigner un Computer ET un Monitor différents. Toujours combiner items_id + itemtype pour identifier un item.

expand_dropdowns indispensable pour les labels

Sans ce paramètre, computertypes_id retourne un number (ex: 4). Avec expand_dropdowns=true on obtient "Laptop".

Search API : résultats dans res.data.data

Contrairement aux autres endpoints, /search/ encapsule les résultats dans { data: [...], count: N, totalcount: N }. Ne pas oublier .data.data.

TicketCost introuvable dans la doc officielle

Jamais mentionné clairement dans la doc API. La table glpi_ticketcosts existe mais le endpoint /Ticket/{id}/TicketCost se découvre via /Ticket/{id}?get_hateoas=true qui liste les sous-ressources disponibles.

Statuts ticket GLPI ≠ 3 colonnes Kanban

GLPI a 6 statuts (1 à 6). Pour un Kanban à 3 colonnes, mapper : Nouveau=1, In Progress=2, Clos=6. Les statuts 3,4,5 peuvent être ignorés ou mappés selon besoin.
